# Chunked Uploads Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let the `quire` CLI publish sessions larger than the 20 MB per-request cap by splitting them into ≤20 MB message-chunks that are appended to a single share, with a `--no-chunk` flag to force a single (possibly 413-ing) upload.

**Architecture:** Chunking lives in the CLI (redaction is byte-stable per message, so a chunk redacts identically to the whole session). The server gains an `uploadId` on each share, a `chunk_seq` on each message, and a new `POST /api/chats/:token/chunks` append endpoint. The public endpoint orders by `(chunk_seq, seq)` with a `chunkSeq:seq` cursor so lazy-loading pages across chunk boundaries. The 20 MB cap is unchanged.

**Tech Stack:** Node 22 + TypeScript, Hono, Drizzle ORM + Postgres (drizzle-kit 0.31.10), zod v4, vitest 3, pnpm workspaces.

## Global Constraints

- **Per-request upload cap stays 20 MB.** `MAX_UPLOAD_BYTES` in `server/src/api/headers.ts:4` is NOT changed. The existing "413 too_large above 20 MB" test in `server/test/middleware.test.ts` is NOT changed.
- **One share across all chunks.** A large session is a single share; chunks are appended in order and the viewer shows the full transcript as one share (never N links).
- **`--no-chunk`** sends the whole session as one upload; over the cap → server `413 too_large` + CLI error telling the user to drop the flag.
- **Server-side redaction is the single authoritative redactor.** Every chunk is redacted by `prepareContent` on the server at append time; the viewer never receives raw secrets.
- **No `share.mikeorozco.dev` reference** anywhere in code/config/docs (host is owner-configured).
- **Migration must be idempotent & safe on an empty live DB.** The live `shares` table is empty (all test shares revoked); the migration runs at server start via `migrateDb`.
- **Test DB container** `quire-test-db` (postgres:16-alpine, port 54329) must be running for server integration tests. Start it with `pnpm db:test:up` if down. NEVER `pnpm db:test:down`.
- **Windows/Git Bash:** git autocrlf converts LF→CRLF (expected warning on generated files); Node `/tmp` resolves to `D:\tmp` (doesn't exist) — use `C:/Users/me/AppData/Local/Temp` if a temp path is needed.
- **Direct invocation (pnpm `--filter` exit-code quirk):** server test `cd server && node node_modules/vitest/vitest.mjs run`; server tsc `cd server && node node_modules/typescript/lib/tsc.js -p tsconfig.json`; cli test `cd cli && node node_modules/vitest/vitest.mjs run`; cli tsc `node cli/node_modules/typescript/lib/tsc.js -p cli/tsconfig.json`; builds via `node <pkg>/node_modules/tsup/dist/index.js`.

```ts
    const body = await c.req.json().catch(() => null);
    const parsed = chunkBodySchema.safeParse(body);
    if (!parsed.success) {
      return c.json({ error: { code: 'validation', message: parsed.error.issues[0]?.message ?? 'invalid body' } }, 400);
    }
    const { uploadId, chunkSeq, messages } = parsed.data;

    const share = rows[0];
    if (!share) return c.json({ error: { code: 'not_found', message: 'Not found' } }, 404);
    if (share.uploadId !== uploadId) {
      return c.json({ error: { code: 'upload_id_mismatch', message: 'uploadId does not match this share' } }, 400);
    }
    const prepared = prepareContent(messages, share.preset as 'strict' | 'normal' | 'none');
    const result = await db.transaction(async (tx) => {
      await tx
        .insert(shareMessages)
        .values(
          prepared.messages.map((m, i) => ({
            shareId: share.id,
            chunkSeq,
            seq: i + 1,
            role: m.role,
            time: m.time ? new Date(m.time) : null,
            parts: m.parts,
          })),
        );
      const [updated] = await tx
        .update(shares)
        .set({
          messageCount: shares.messageCount! + prepared.messageCount,
          bytes: shares.bytes! + prepared.bytes,
          redactions: sql`(${shares.redactions}) || ${JSON.stringify(prepared.summary)}::jsonb`,
        })
        .where(eq(shares.id, share.id))
        .returning();
      return updated;
    });
    return c.json({ ok: true, messageCount: result!.messageCount, bytes: result!.bytes });
  });
```

```ts
interface Cursor { chunkSeq: number; seq: number }
function parseCursor(raw: string | undefined): Cursor {
  if (raw === undefined) return { chunkSeq: 0, seq: 0 };
  const idx = raw.indexOf(':');
  if (idx < 0) return { chunkSeq: 0, seq: 0 };
  const chunkSeq = Number.parseInt(raw.slice(0, idx), 10);
```

```ts
import type { ShapedMessage } from './harness/types.js';

/** Per-request cap is 20 MB (server MAX_UPLOAD_BYTES). Target slightly under so the
 *  JSON envelope (session header + create/chunk wrapper) still fits under the cap. */
export const CHUNK_TARGET_BYTES = 19 * 1024 * 1024;

/**
 * Greedily pack messages into chunks whose serialized size is <= maxBytes.
 * Order is preserved. A single message larger than maxBytes gets its own chunk
 * (it will 413 server-side; such a message is pathological). Empty input -> [].
 */
export function chunkMessages(messages: ShapedMessage[], maxBytes: number = CHUNK_TARGET_BYTES): ShapedMessage[][] {
  if (messages.length === 0) return [];
  const chunks: ShapedMessage[][] = [];
  let current: ShapedMessage[] = [];
  let size = 0;
  for (const m of messages) {
    const mSize = Buffer.byteLength(JSON.stringify(m));
    // If the current chunk is empty, start it with this message even if it alone
    // exceeds maxBytes (avoids an infinite loop on a pathological single message).
    if (current.length > 0 && size + mSize > maxBytes) {
      chunks.push(current);
      current = [];
      size = 0;
    }
    current.push(m);
    size += mSize;
  }
  if (current.length > 0) chunks.push(current);
  return chunks;
}
```
